Signature Platform: AWS architecture

Signature detection (RF-DETR Large) + similarity (DINOv2), queue-based workers, and automatic retraining from Hugging Face. All components MIT / Apache / BSD.

Inference request flowRetraining & deployment flow

Inference flow

  1. Client sends a document (and a reference signature for verify) over HTTPS to the ALB.
  2. FastAPI validates the file, stores it in S3 and puts a job on the SQS inference queue. It returns a job id at once.
  3. A GPU worker takes the job: RF-DETR Large finds the signatures, DINOv2 scores each one against the reference.
  4. The worker writes the result to ElastiCache and deletes the upload from S3.
  5. The client polls /v1/jobs/{id} and gets boxes, confidences, similarity scores and match yes/no.

Retraining & deployment flow

  1. New labelled images are pushed to the private Hugging Face dataset; HF calls the webhook.
  2. FastAPI checks the secret and queues a training job on the SQS training queue.
  3. The on-demand GPU trainer picks it up.
  4. It downloads that exact dataset revision from Hugging Face.
  5. It trains RF-DETR Large, evaluates on the test split, and logs everything to MLflow (artifacts in S3).
  6. If the new mAP50 beats production, the model gets the @production alias; workers hot-reload it within 60 s.
